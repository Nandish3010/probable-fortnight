CONCLUSION: bare `python` reproduces the exact 27 Sep failure
("ModuleNotFoundError: No module named 'google'") byte-for-byte. google-cloud-bigquery is
installed only into uv's managed virtualenv (.venv), which `uv sync --frozen --no-dev` creates;
the base image's bare `python` interpreter (system site-packages) never sees it. infra/deploy.sh's
`--command python --args="-m,jobs.sense"` (and jobs.measure) invoked that bare interpreter
directly, bypassing uv entirely -- exactly the bug this PR fixes, matching the Firestore-mirror
job at deploy.sh:237 which already used the correct `--command uv --args="run,python,..."` form.
No further investigation needed: this is the root cause, not a secondary symptom.
